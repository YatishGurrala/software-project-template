**Last Updated:** YYYY-MM-DD

This document is the source of truth for high-level product capabilities and features.

---

## Guidance for Updating Features

- **Product-Level Scope:** This file tracks product capabilities and features, not fine-grained coding tasks or bug tickets.
- **Status Integrity:** Update status only when actual implementation reality changes.
- **Definition of Done for Features:** Do not mark a feature `DONE` if only UI mockups, partial backend endpoints, or placeholders exist, unless that specific subset was the explicitly approved scope.
- **Preserve History:** Keep completed features (`DONE`) in the table rather than deleting them, so full capability history remains transparent.

---

## Allowed Statuses

- `IDEA`: Conceptual capability under consideration.
- `PLANNED`: Approved capability queued for development.
- `IN_PROGRESS`: Actively under development.
- `BLOCKED`: Development halted due to an external dependency, bug, or decision requirement.
- `DONE`: Fully implemented, validated, and integrated.
- `DEFERRED`: Deprioritized or postponed for a future milestone.

---

## Allowed Priorities

- `P0`: Critical / Blocker (Must-have for launch/milestone)
- `P1`: High priority (Core capability)
- `P2`: Medium priority (Important improvement or extension)
- `P3`: Low priority (Nice-to-have / polish)
